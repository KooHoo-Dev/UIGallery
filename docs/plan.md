## 3. 콘텐츠 정책

### 한다
- 원작의 **패턴과 원리**(레이아웃 구조, 정보 위계, 상태 전이, 모션 타이밍)를 분석해 **새 코드로 재구성**한다.
- 원작에서 빌려 오는 시각 축은 **최대 2개**(색 체계, 형태·기울기, 레이아웃 구조, 모션 리듬, 타이포 성격 중). 나머지는 새로 만든다.
- 원작은 공식 사이트·스토어·공식 영상·GDC 강연 등 **외부 링크로만** 연결한다.
- 에셋은 라이선스가 확인된 것만 쓴다. 폰트는 OFL, 아이콘은 직접 그린 SVG 또는 CC0·ISC, 사운드는 WebAudio 합성 또는 CC0.

### 하지 않는다
- 게임 파일에서 스프라이트·아이콘·폰트·로고·사운드를 **추출(리핑)**하지 않는다.
- 원작 화면을 **따라 그리지(트레이싱)** 않는다. AI에게 "이 스크린샷과 똑같이"를 시키지도 않는다.
- 로고, 키 아트, 캐릭터(실루엣 포함), 엠블럼, 고유 아이콘, 게임 고유 문구, 전용 서체(팬 복제 폰트 포함)를 쓰지 않는다.
- 한 화면의 구도·전환·모티프를 **통째로** 재현하지 않는다.
- 스크린샷을 리포에 커밋하지 않는다. 임시로도 하지 않는다.
- Game UI Database에 에이전트가 접근하지 않는다(사이트가 AI 접근과 AI 용도를 금지). 사람이 여는 참고 링크로만 쓴다.

### 표기
- **표본 제목과 코드 ID는 패턴 이름**으로 짓는다. 예: `slanted-kinetic-menu`, `P5Menu` 같은 이름은 쓰지 않는다.
- 게임명은 `inspiredBy` 메타데이터와 크레딧에만 쓴다.
  예: `Inspired by: Persona 5 Royal (© ATLUS © SEGA) · 빌린 것: 고대비 3색, 사선 패널 · 새로 만든 것: 타이포, 아이콘, 카피`
- 프리셋 이름은 게임명 대신 장르나 원리로 짓는다. 예: `소울라이크`, `택티컬 FPS`, `카툰 액션`
- 사이트 공통 고지:
  > 이 갤러리의 UI는 모두 새로 작성한 학습용 재해석이며, 원작 게임의 이미지·폰트·사운드·로고를 포함하지 않습니다. 언급된 게임명과 상표는 각 권리자의 소유이며, 본 프로젝트는 해당 권리자와 제휴하거나 보증받지 않았습니다.
- 앱 안에 '크레딧·라이선스' 패널을 둔다(React·three.js MIT, 폰트 OFL 등). 리포에는 `LICENSE`(코드 MIT, 게임명·상표 제외 명시)를 둔다.

## 4. 기술 구성

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + `vite-plugin-singlefile` | 결과물이 HTML 1개. 더블클릭(file://)과 Pages에서 똑같이 동작 |
| UI | React 19 + TypeScript | 타입 검사로 여러 에이전트가 만든 표본의 계약 위반을 빌드 시 잡음 |
| 3D | three.js + React Three Fiber + drei `<View>` | **Canvas 1개를 공유**(WebGL 페이지당 16개 제한). 3D는 상세 화면에서만, 안 될 때 2D 폴백 |
| 모션 | motion (MIT) | 스프링, 시퀀스, 슬로모션 배속을 공통 시계로 제어 |
| 스타일 | CSS Modules + CSS 변수 토큰 | 표본끼리 스타일이 섞이지 않음. Tailwind는 쓰지 않음 |
| 라우팅 | 해시 라우터 `#/hud/health-bar` | file://와 Pages 모두 동작. 표본 ID는 영구 불변 |
| 폰트 | 한글은 시스템 폰트(맑은 고딕), 게임풍 영문·숫자만 OFL 웹폰트 소량 | 한글 웹폰트는 굵기 하나에 약 270KB |
| 코드 표시 | Unity 코드는 실제 파일(`.cs`, `.uxml`, `.uss`)을 `?raw`로 읽어 하이라이트 | 앱에 보이는 코드와 Unity에서 컴파일하는 코드가 같은 파일 |
| 용량 예산 | HTML 1개 원본 5MB · gzip 1.5MB 이하 (2026-10-23 3MB에서 상향) | 비트맵 0, 폰트 400KB 이하. 표본별 증분은 `npm run size` |

> **예산 상향 근거 (2026-10-23 실측)**: 표본 1개가 평균 +114KB(gzip +36KB)라 3MB로는 2개밖에 더 못 넣었다. 그런데 첫 화면 시간을 잡아먹는 건 바이트가 아니라 홈 카드마다 무대를 만드는 일이었다(홈 172ms vs 상세 84ms, 표본 전체를 읽고 실행하는 비용은 30~70ms). 그래서 예산은 올리고 홈 카드 무대는 화면 근처에 올 때 만들도록 바꿨다. 분할 로딩은 file:// 에서 모듈 청크를 못 읽어 더블클릭 실행이 깨지므로 쓰지 않고, 압축 자체 해제 HTML은 1.14MB까지 줄지만 Pages 전송량 이득이 없고 상세 화면이 느려져 보류했다.

### 배포
- `main`에 push하면 GitHub Actions가 빌드해 Pages에 배포한다.
- 사이트 상단 **"오프라인용 HTML 받기"** 버튼을 누르면 같은 파일을 내려받는다. 버전 태그를 붙이면 Release에도 첨부한다.
- 강사님이 GitHub 웹에서 해설 Markdown을 고쳐 커밋하면 자동으로 다시 빌드되어 반영된다. 로컬 Node가 없어도 된다.

### 폴더 구조 (0.5단계에서 확정)
```
UIGallery/
├─ docs/                     # plan.md, agent-contract.md
├─ research/                 # 리서치 결과 JSON (텍스트·URL만, 이미지 금지)
├─ src/
│  ├─ app/                   # 셸, 라우터, 무대, 컨트롤 패널, 재생 바, 발표 모드
│  ├─ three/                 # 공유 Canvas, 무대 3D 씬, WebGL 폴백
│  ├─ specimens/<id>/        # 표본 1개 = 폴더 1개 (index.tsx, meta.ts, *.module.css)
│  ├─ content/<id>.md        # 해설·흔한 실수·과제 (강사 편집 대상)
│  └─ unity/<id>/ugui|uitk/  # 실제 Unity 코드 (6.3에서 컴파일 확인)
├─ tools/                    # 검사 스크립트 (Python): 외부 URL 0, 파일명 규칙, 링크 생존
└─ .github/workflows/deploy.yml
```
표본 목록은 `import.meta.glob`으로 자동 등록한다. 에이전트가 각자 자기 폴더만 만들면 되므로 병렬 작업 중 충돌이 없다.
